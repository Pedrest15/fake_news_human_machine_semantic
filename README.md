# Automatic Discrimination of Human- and Machine-Produced Fake News for Brazilian Portuguese

Code and results for a study on **Brazilian Portuguese fake news**, comparing texts
written by humans against texts generated by Large Language Models (LLMs).

The repository contains four independent analysis modules plus a classification
pipeline that combines all of them:

| Module | What it does |
|---|---|
| [`ed_rules/`](ed_rules/) | Extracts dependency-grammar rules from CoNLL-U files (with Enhanced Universal Dependencies) and compares them across groups |
| [`liwc/`](liwc/) | Runs LIWC psycholinguistic category analysis over the corpus |
| [`nilc-metrix/`](nilc-metrix/) | Runs the NILC-Metrix readability/cohesion/complexity metrics and ranks the discriminative ones |
| [`linguistic_features/`](linguistic_features/) | Human vs. LLM classification from linguistic features, BERT embeddings, or both |

Every module writes both machine-readable (CSV/JSON) and human-readable (TXT/MD)
outputs, and the versioned result files are kept in the repository.

## Results website

An interactive summary of every result in this repository is published with GitHub
Pages from the [`docs/`](docs/) folder.

```bash
# Regenerate docs/index.html from the committed result files
python3 tools/build_docs.py

# Preview locally
python3 -m http.server -d docs 8000    # then open http://localhost:8000
```

The page is a single self-contained HTML file — no build step, no external assets.
[`tools/build_docs.py`](tools/build_docs.py) reads the JSON/CSV artefacts and injects
them into [`tools/docs_template.html`](tools/docs_template.html), so every number on
the page traces back to a file in this repository. Re-run it whenever results change.

To enable publishing: **Settings → Pages → Source: Deploy from a branch → `main` / `docs`**.

## Corpus

Two paired fake-news corpora are used. For each human-written document there is a
matching LLM-generated counterpart with the same filename, which makes the
comparison strictly paired.

| Corpus | Human | LLM | Total |
|---|---|---|---|
| FakeTrue.Br | 1,791 | 1,791 | 3,582 |
| Fake.Br | 3,600 | 3,600 | 7,200 |
| **Total** | **5,391** | **5,391** | **10,782** |

The underlying data this work builds on comes from
[renatosvmor/fake-news-llm-ptbr](https://github.com/renatosvmor/fake-news-llm-ptbr).

The raw corpora and the pre-computed feature files are **not** versioned here
(see `.gitignore`); they are copied into `linguistic_features/data/` locally.

## Setup

```bash
# Python 3.13+
uv sync
```

Some modules need extra, external components:

- **`ed_rules/`** — [Grew](https://grew.fr/usage/install/) must be on `PATH`, and the
  parsed CoNLL-U files must be reachable through the `portparser_results/` symlink.
- **`liwc/`** — the LIWC2015 Brazilian Portuguese dictionary is proprietary. Obtain
  it from <https://www.liwc.app/> and place it at
  `liwc/Brazilian_Portuguese_LIWC2015_dictionary.dic`.
- **`nilc-metrix/`** — requires the `cohmetrix:focal` Docker image and the
  NILC-Metrix source tree in `nilc-metrix/nilcmetrix/`.

## `ed_rules/` — Enhanced Dependency rule extraction

Extracts dependency-grammar patterns from CoNLL-U files. Before extraction, the
files are enriched with Enhanced Universal Dependencies using the Grew rule set from
[alvelvis/eud-portugues](https://github.com/alvelvis/eud-portugues).

> `conjunto_regras_porttinari.grs` is vendored verbatim from that upstream project;
> its name and contents are kept unchanged so it stays traceable to the original.

### Catalogue the Grew rules as JSON

```bash
python3 -m ed_rules.grs_catalog \
    ed_rules/conjunto_regras_porttinari.grs \
    aggregated_output/eud_rules_catalog.json
```

### Apply EUD to a directory of `.conllu` files

```bash
python3 -m ed_rules.eud_runner \
    portparser_results/fake_true_human \
    portparser_results_eud/fake_true_human \
    --strategy eud_portuguese
```

### Full pipeline

`main.py` always pre-processes the `.conllu` files with the eud-portugues Grew rules
before extraction — there is no flag to skip it.

```bash
python3 ed_rules/main.py
```

This runs, in order:

1. per-file `.rules.json` generation for ED-only rules (`rules_output_ed/`);
2. per-file `.rules.json` generation for all rules (`rules_output_all/`);
3. the aggregated Human vs. LLM statistical comparison (`human_llm_comparison/`);
4. TF-IDF discriminative analysis for both rule sets (`tfidf_output/`).

### Look up the sentences behind a rule

```bash
python3 ed_rules/find_rule_sentences.py "NOUN(*, NOUN/nmod:de)"
python3 ed_rules/find_rule_sentences.py "VERB(*, VERB/advcl:porque)" --group fake_br_human
```

### Outputs

- `human_llm_comparison/rule_statistical_tests.csv` — t-test, Mann-Whitney U and
  Cohen's d for rules-per-sentence and unique-rules-per-sentence
- `tfidf_output/discriminative_rules_{with,without}_repetition.csv` — every rule
  ranked by how discriminative it is
- `tfidf_output/top_rules_{human,llm}_*.csv` — the most characteristic rules per group

## `liwc/` — LIWC psycholinguistic analysis

Scores every document against the LIWC2015 categories and compares the groups with
Mann-Whitney U and Cohen's d.

```bash
python3 -m liwc.main                       # uses the default dictionary path
python3 -m liwc.main /path/to/dictionary.dic
```

### Outputs (`liwc/liwc_output/`)

- `liwc_results.md` — narrative report of the findings
- `liwc_discriminative_categories.csv` / `.txt` — every category with full statistics
- `liwc_per_document_scores.csv` — per-document LIWC scores, ready for ML
- `liwc_analysis_summary.txt` — overall summary

## `nilc-metrix/` — NILC-Metrix textual metrics

### 1. Compute the metrics (inside the Docker container)

```bash
./nilc-metrix/run_batch.sh /path/to/dataset
```

Expects `/data/human/<subset>/*.txt` and `/data/llm/<subset>/*.txt` inside the
container, and writes `results/human.csv` and `results/llm.csv`.

### 2. Compare and rank

```bash
python3 nilc-metrix/analyze_metrics.py             # all metrics, Cohen's d + FDR
python3 nilc-metrix/rank_discriminative_metrics.py # complexity/cohesion/semantics only
```

### Outputs (`nilc-metrix/analysis/`)

- `full_comparison.csv` — every metric ranked by |Cohen's d|
- `top_human.csv` / `top_llm.csv` — top 20 per group (FDR < 0.05)
- `ranked_filtered.csv` — filtered metrics ranked by |Cliff's δ|
- `strong_signals.csv` — |δ| ≥ 0.330 and q < 0.05
- `table_human.tex` / `table_llm.tex` — LaTeX tables of the strong signals

## `linguistic_features/` — Human vs. LLM classification

Classifies each document as human-written or LLM-generated. Three input modes are
available:

- `linguistic` — pre-computed features only (NILC-Metrix + LIWC + Enhanced-UD +
  syllables + POS + parser stats + SAGE terms)
- `embedding` — the frozen BERT `[CLS]` embedding only (BERTimbau or multilingual BERT)
- `combined` — the concatenation of both

Methodology: pre-defined splits, human/LLM pairing by filename with paired
truncation to the shorter member of the pair, `GridSearchCV` with `GroupKFold` on the
training set, and a final evaluation on the held-out test set.

```bash
# All classifiers on the combined vector
python3 linguistic_features/linguistic_features.py --feature-mode combined --classifier all

# Only a subset of the linguistic feature groups
python3 linguistic_features/linguistic_features.py --feature-mode linguistic --features nilcmetrics,liwc

# Embeddings only
python3 linguistic_features/linguistic_features.py --feature-mode embedding --bert-model bertimbau
```

### Related experiments

```bash
# One feature module at a time, to measure each module on its own
python3 linguistic_features/module_classification.py

# Hand-picked top-10 features per module
python3 linguistic_features/top_features_classification.py

# TF-IDF / Bag-of-Words over the text, enriched with linguistic features
python3 linguistic_features/text_enriched.py --vectorizer tfidf --classifier all

# Which features carry the discriminative signal
python3 linguistic_features/feature_diagnostic.py
```

### Outputs (`linguistic_features/results/`)

- `<experiment>_<classifier>.json` — metrics, best hyper-parameters, feature importance
- `confusion_matrices/*.png` — confusion matrices
- `misclassified/*_errors.json` — misclassified documents with their probabilities
- `comparison_*.json` — classifier comparison per experiment
- `modules/`, `top_features/` — results of the per-module and top-feature experiments
- `feature_diagnostic_ranking.csv` — every feature ranked by univariate F1

> Some feature and column names (e.g. `syll__media_silabas_por_sentenca`,
> `nilc__concretude_mean`) are inherited verbatim from the upstream characterisation
> pipeline, which emits them in Portuguese. They are kept as-is so the pre-computed
> data files do not need to be regenerated.
