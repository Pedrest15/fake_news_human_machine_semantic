# Automatic Discrimination of Human- and Machine-Produced Fake News for Brazilian Portuguese

Code and results for a study on **Brazilian Portuguese fake news**, comparing texts
written by humans against texts generated by Large Language Models (LLMs).

The repository contains four independent analysis modules plus a classification
pipeline that combines all of them:

| Module | What it does |
|---|---|
| [`ed_rules/`](ed_rules/) | Extracts dependency-grammar rules from CoNLL-U files (with Enhanced Universal Dependencies) and compares them across groups |
| [`liwc/`](liwc/) | Runs LIWC psycholinguistic category analysis over the corpus |
| [`nilc-metrix/`](nilc-metrix/) | Runs the NILC-Metrix readability/cohesion/complexity metrics and ranks the discriminative ones |
| [`linguistic_features/`](linguistic_features/) | Human vs. LLM classification from linguistic features, BERT embeddings, or both |

Every module writes both machine-readable (CSV/JSON) and human-readable (TXT/MD)
outputs. The characterisation outputs of `ed_rules/`, `liwc/` and `nilc-metrix/` are
versioned; the classification results under `linguistic_features/results/` are
generated by running the scripts and are not shipped (see
[Reproducing the experiments](#reproducing-the-experiments)).

## Corpus

Two paired fake-news corpora are used. For each human-written document there is a
matching LLM-generated counterpart with the same filename, which makes the
comparison strictly paired.

| Corpus | Human | LLM | Total |
|---|---|---|---|
| FakeTrue.Br | 1,791 | 1,791 | 3,582 |
| Fake.Br | 3,600 | 3,600 | 7,200 |
| **Total** | **5,391** | **5,391** | **10,782** |

The human-written articles come from the Fake.Br and FakeTrue.Br corpora; their
LLM-generated counterparts (Sabiá-3) come from
[renatosvmor/fake-news-llm-ptbr](https://github.com/renatosvmor/fake-news-llm-ptbr).

The raw corpora and the pre-computed feature files are **not** versioned here
(see `.gitignore`); they are copied into `linguistic_features/data/` locally. The
parsed CoNLL-U files in `ed_rules/portparser_results_eud/` *are* versioned and carry
the full article text (`# text =` lines).

### Data and responsible use

- The license in this repository covers the **code**. The corpora, and the parsed
  files derived from them, keep the terms of their original sources: check them
  before reusing or redistributing the data.
- The texts are fake news, human-made and LLM-generated, and some mention real people.
  A few source articles contain personal contact data (e-mail addresses, phone
  numbers). The data is provided for research on authorship detection and must not be
  used to produce or spread disinformation.

## Setup

```bash
# Python 3.13+
uv sync
```

Some modules need extra, external components:

- **`ed_rules/`** — [Grew](https://grew.fr/usage/install/) must be on `PATH`, and the
  parsed CoNLL-U files must be reachable through the `portparser_results/` symlink.
- **`liwc/`** — the LIWC2015 Brazilian Portuguese dictionary is proprietary. Obtain
  it from <https://www.liwc.app/> and place it at
  `liwc/Brazilian_Portuguese_LIWC2015_dictionary.dic`.
- **`nilc-metrix/`** — requires the `cohmetrix:focal` Docker image and the
  NILC-Metrix source tree in `nilc-metrix/nilcmetrix/`.

## `ed_rules/` — Enhanced Dependency rule extraction

Extracts dependency-grammar patterns from CoNLL-U files. Before extraction, the
files are enriched with Enhanced Universal Dependencies using the Grew rule set from
[alvelvis/eud-portugues](https://github.com/alvelvis/eud-portugues).

> `conjunto_regras_porttinari.grs` is vendored verbatim from that upstream project;
> its name and contents are kept unchanged so it stays traceable to the original.

### Catalogue the Grew rules as JSON

```bash
python3 -m ed_rules.grs_catalog \
    ed_rules/conjunto_regras_porttinari.grs \
    aggregated_output/eud_rules_catalog.json
```

### Apply EUD to a directory of `.conllu` files

```bash
python3 -m ed_rules.eud_runner \
    portparser_results/fake_true_human \
    portparser_results_eud/fake_true_human \
    --strategy eud_portuguese
```

### Full pipeline

`main.py` always pre-processes the `.conllu` files with the eud-portugues Grew rules
before extraction — there is no flag to skip it.

```bash
python3 ed_rules/main.py
```

This runs, in order:

1. per-file `.rules.json` generation for ED-only rules (`rules_output_ed/`);
2. per-file `.rules.json` generation for all rules (`rules_output_all/`);
3. the aggregated Human vs. LLM statistical comparison (`human_llm_comparison/`);
4. TF-IDF discriminative analysis for both rule sets (`tfidf_output/`).

### Look up the sentences behind a rule

```bash
python3 ed_rules/find_rule_sentences.py "NOUN(*, NOUN/nmod:de)"
python3 ed_rules/find_rule_sentences.py "VERB(*, VERB/advcl:porque)" --group fake_br_human
```

### Outputs

- `human_llm_comparison/rule_statistical_tests.csv` — t-test, Mann-Whitney U and
  Cohen's d for rules-per-sentence and unique-rules-per-sentence
- `tfidf_output/discriminative_rules_{with,without}_repetition.csv` — every rule
  ranked by how discriminative it is
- `tfidf_output/top_rules_{human,llm}_*.csv` — the most characteristic rules per group

## `liwc/` — LIWC psycholinguistic analysis

Scores every document against the LIWC2015 categories and compares the groups with
Mann-Whitney U and Cohen's d.

```bash
python3 -m liwc.main                       # uses the default dictionary path
python3 -m liwc.main /path/to/dictionary.dic
```

### Outputs (`liwc/liwc_output/`)

- `liwc_results.md` — narrative report of the findings
- `liwc_discriminative_categories.csv` / `.txt` — every category with full statistics
- `liwc_per_document_scores.csv` — per-document LIWC scores, ready for ML
- `liwc_analysis_summary.txt` — overall summary

## `nilc-metrix/` — NILC-Metrix textual metrics

### 1. Compute the metrics (inside the Docker container)

```bash
./nilc-metrix/run_batch.sh /path/to/dataset
```

Expects `/data/human/<subset>/*.txt` and `/data/llm/<subset>/*.txt` inside the
container, and writes `results/human.csv` and `results/llm.csv`.

### 2. Compare and rank

```bash
python3 nilc-metrix/analyze_metrics.py             # all metrics, Cohen's d + FDR
python3 nilc-metrix/rank_discriminative_metrics.py # complexity/cohesion/semantics only
```

### Outputs (`nilc-metrix/analysis/`)

- `full_comparison.csv` — every metric ranked by |Cohen's d|
- `top_human.csv` / `top_llm.csv` — top 20 per group (FDR < 0.05)
- `ranked_filtered.csv` — filtered metrics ranked by |Cliff's δ|
- `strong_signals.csv` — |δ| ≥ 0.330 and q < 0.05
- `table_human.tex` / `table_llm.tex` — LaTeX tables of the strong signals

## `linguistic_features/` — Human vs. LLM classification

Classifies each document as human-written or LLM-generated. Three input modes are
available:

- `linguistic` — pre-computed features only (NILC-Metrix + LIWC + Enhanced-UD +
  syllables + POS + parser stats + SAGE terms)
- `embedding` — the frozen encoder embedding only (BERTimbau or multilingual BERT)
- `combined` — the concatenation of both

Methodology: pre-defined 80/20 splits (`train_*.txt` / `test_*.txt`: 4,312 training
and 1,079 test pairs, i.e. 8,624 and 2,158 documents), human/LLM pairing by filename
with paired truncation to the shorter member of the pair, `GridSearchCV` with
`GroupKFold` on the training set (a pair never crosses folds), weighted F1 as the
selection metric, and a single final evaluation on the held-out test set. The seed is
42 everywhere.

```bash
# All classifiers on the combined vector
python3 linguistic_features/linguistic_features.py --feature-mode combined --classifier all

# Only a subset of the linguistic feature groups
python3 linguistic_features/linguistic_features.py --feature-mode linguistic --features nilcmetrics,liwc

# Embeddings only
python3 linguistic_features/linguistic_features.py --feature-mode embedding --bert-model bertimbau
```

### Encoders

`--bert-model` selects the frozen encoder used by the `embedding` and `combined`
modes, and its tokenizer is what drives the paired truncation everywhere:

| Key | Hugging Face id | Dim | Context | Default pooling |
|---|---|---:|---:|---|
| `bertimbau` (default) | `neuralmind/bert-base-portuguese-cased` | 768 | 512 | `cls` |
| `bert-multilingual` | `bert-base-multilingual-cased` | 768 | 512 | `cls` |

`--pooling auto` (the default) uses the `[CLS]` vector; `--pooling mean` averages the
tokens over the attention mask, for ablations.

Result files are prefixed with the feature mode plus a suffix for every setting
that is not the default — the encoder, the pooling and the token cap — so a new
battery never overwrites the previous one: `combined_svm.json` (BERTimbau +
`[CLS]` + 512), `combined_bert_multilingual_svm.json` (multilingual BERT),
`embedding_len256_svm.json` (256-token cap). That
covers the JSON, the confusion matrix, the misclassified list and the classifier
comparison. The embedding cache in `linguistic_features/cache/` is keyed the same
way, so runs at different token caps coexist instead of invalidating each other.
`--experiment-label` overrides the whole prefix when you want to name a run
yourself.

```bash
# Same battery on multilingual BERT (comparable to BERTimbau)
python3 linguistic_features/linguistic_features.py --feature-mode combined --bert-model bert-multilingual --classifier all
python3 linguistic_features/linguistic_features.py --feature-mode embedding --bert-model bert-multilingual --classifier all
```

### BERT fine-tuning

`bert_finetuning.py` fine-tunes BERTimbau or multilingual BERT end to end
(`AutoModelForSequenceClassification`, 2 labels) with the same protocol as the
classifiers above: the pre-defined 80/20 split by pair, paired truncation, and
5-fold cross-validation on the training part grouped by pair. The best fold (by
validation weighted F1) is evaluated once on the test set. Defaults: AdamW,
learning rate 5e-5, batch size 8, 3 epochs, 500 warm-up steps, weight decay 0.01,
early stopping (patience 3, every 500 steps), seed 42. It needs a GPU in practice.

```bash
python3 linguistic_features/bert_finetuning.py --bert-model bertimbau
python3 linguistic_features/bert_finetuning.py --bert-model bert-multilingual

# [CLS] embeddings of the fine-tuned encoder (best fold) fed to the six classifiers
python3 linguistic_features/finetuned_embeddings.py --bert-model bertimbau
```

Checkpoints go to `linguistic_features/models/` (git-ignored); results to
`linguistic_features/results/finetune_<model>.json` and
`finetuned_embedding_<model>_*.json`.

### Preprocessing and missing features

Imputation, standardisation, BoW/TF-IDF vectorisation and `--top-k` selection live
inside the model pipeline, so they are refitted on the training part of every CV fold
and never see the validation fold or the test set. Documents missing from some
linguistic group (e.g. POS tagger output) are kept by default and their gaps filled with
the training median (`--missing-features impute`), so every condition is evaluated on
the same test set; `--missing-features drop` restores the inner join.

Length bias is controlled at the feature level: absolute counts and length-dependent
metrics are dropped from NILC-Metrix, the LIWC metadata fields and aggregate categories
are dropped, and for the parser statistics only the length-normalised
`psr__rules_per_sentence` is kept (the raw sentence/rule counts encode text size).
`--keep-nilc-absolute` disables this filtering for ablations.

### Reproducing the experiments

| Experiment | Command |
|---|---|
| Frozen encoder + classifiers | `linguistic_features.py --feature-mode embedding --bert-model bertimbau` (or `bert-multilingual`) |
| Fine-tuned encoder | `bert_finetuning.py --bert-model bertimbau` (or `bert-multilingual`) |
| Fine-tuned encoder embeddings + classifiers | `finetuned_embeddings.py --bert-model bertimbau` |
| BoW / TF-IDF, no linguistic features | `text_enriched.py --vectorizer both --no-linguistic` |
| BoW / TF-IDF + linguistic features | `text_enriched.py --vectorizer both` |
| Linguistic features, module by module | `module_classification.py` |
| Ten hand-picked features per module | `top_features_classification.py` |

All scripts are run from the repository root as `python3 linguistic_features/<script>`.

### Classifiers

Six classifiers are tuned by grid search: SVM, Random Forest, Gaussian Naive Bayes,
Logistic Regression, MLP and XGBoost. Two grids are used:

- **Grid A** (`CLASSIFIERS_CONFIG` in `linguistic_features.py`) — linguistic,
  embedding and combined representations, including the module and top-k experiments;
- **Grid B** (`CLASSIFIERS_CONFIG` in `text_enriched.py`) — the smaller grid for
  BoW/TF-IDF.

Settings outside the grids are fixed in the code (`SVC(probability=True)`,
`LogisticRegression(max_iter=1000)`, `MLPClassifier(max_iter=500, early_stopping=True)`,
`XGBClassifier(eval_metric="logloss")`, `random_state=42`); everything else keeps the
scikit-learn / XGBoost defaults. Feature importances are impurity-based for Random
Forest, gain-based for XGBoost and `|coef|` for Logistic Regression and linear SVMs.

### Related experiments

```bash
# One feature module at a time, to measure each module on its own
python3 linguistic_features/module_classification.py

# Hand-picked top-10 features per module
python3 linguistic_features/top_features_classification.py

# TF-IDF / Bag-of-Words over the text, enriched with linguistic features
python3 linguistic_features/text_enriched.py --vectorizer tfidf --classifier all

# Same baseline, but truncating the pairs with the multilingual BERT tokenizer
python3 linguistic_features/text_enriched.py --vectorizer tfidf --bert-model bert-multilingual

# Which features carry the discriminative signal
python3 linguistic_features/feature_diagnostic.py
```

### Outputs (`linguistic_features/results/`)

Created on the first run (the directory is not shipped):

- `<experiment>_<classifier>.json` — metrics, best hyper-parameters, feature importance
- `confusion_matrices/*.png` — confusion matrices
- `misclassified/*_errors.json` — misclassified documents with their probabilities
- `comparison_*.json` — classifier comparison per experiment
- `modules/`, `top_features/` — results of the per-module and top-feature experiments
- `finetune_<model>.json`, `finetuned_embedding_<model>_*.json` — fine-tuning results
- `feature_diagnostic_ranking.csv` — every feature ranked by univariate F1

> Some feature and column names (e.g. `syll__media_silabas_por_sentenca`,
> `nilc__concretude_mean`) are inherited verbatim from the upstream characterisation
> pipeline, which emits them in Portuguese. They are kept as-is so the pre-computed
> data files do not need to be regenerated.
